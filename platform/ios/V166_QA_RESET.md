# v166 — Fresh test profiles, protected reset, reusable 60k test credit

## Goal

The physical iPad already passed v165's save/export and restore tests. The user's true **60,000-PvZCoin reference snapshot lives outside the app** (iCloud Drive or PC); the CURRENT live installation is depleted. v166 must prepare a DIFFERENT, fresh live set of accounts without touching the reference.

**Do not uninstall the app. Do not put the external reference into PvZ2RestoreInbox before choosing the fresh reset.** Every `save-...` snapshot contains ALL accounts as of that snapshot date, plus host config; it is not one folder per player.

## Install and reset

1. Verify that the complete original `save-...` directory from the 60k account is visible **in iCloud Drive or on a PC**, not just `On My iPad > PvZ2forIOS Probe`. Do not delete or modify the original.
2. Update v165 to this v166 IPA **in place** through the existing AltStore/iLoader process. Keep the same app identifier so the current iOS sandbox persists. The fresh-reset option will not erase anything until it is explicitly confirmed.
3. At the first launch, the launcher asks `Nouvelle partie de test ?` if it detects existing data. Press `Réinitialiser mes données locales`. `Garder mes profils actuels` is non-destructive; after declining, reset remains accessible from the in-game stop menu.
4. The launcher first creates an ordinary verified snapshot under `Files > On My iPad > PvZ2forIOS Probe > PvZ2Backups > save-...-prereset-...` and a SECOND verified, non-rotating local snapshot under `Files > On My iPad > PvZ2forIOS Probe > PvZ2ProtectedResets > save-...-prereset-...`. Only after confirming hashes and unchanged source inventory does it move all active `UserData*` (including old QA dirs) and `config-v1.txt` into rollback and start the old runtime. The imported APK, OBB, external cloud data and restore inbox are not reset.
5. The former config marker `offline_store_test_coin_grant_60000_v1` was cleared by the full reset. Create a fresh account A. Once the guest recognizes A, the unchanged v162/v165 QA logic should grant the first new account a **one-time 60,000-PvZCoin FLOOR**, not 60k every time the app starts. Confirm actual coin amount and `OFFLINE STORE TEST COINS ... markerPersisted=YES` in the complete log.
6. Create a separate empty B. Use the documented same-process purchase-A → switch-B → first CLAIM/BUY capture, followed by stop+full log and a cold-restart second full log. Details: `docs/V166_CLAIM_AB_RESTORE_TEST.md`. Preserve both BEFORE restoring the cloud reference.

## Repeating a reset without another IPA

While playing, tap the upper-left `⋯` then `Sauvegarder et arrêter`. When execution has stopped, tap `⋯` again, select `Réinitialiser pour tests…`, then confirm. It makes a NEW protected snapshot before clearing all local user data and config. **Fully force-quit the app and cold relaunch** so neither previous guest RAM state nor the old in-memory config survives. A fresh first profile should receive the one-time test grant again.

## Failure safety

- Failure to copy/verify EITHER backup or changed live inventory stops reset before modifying live data.
- Files are moved root-by-root into an out-of-tree rollback area, and already-moved roots are moved back if another move fails; any nonempty rollback area is retained for forensic recovery.
- The startup dialog pauses guest launch on a reset error and shows the actual filesystem failure. No automatic retry or silent fallback into a running old account.
- The protected reset snapshots do not participate in the 12-copy rotation of ordinary `PvZ2Backups`. They are still IN the app's sandbox and should also be copied to iCloud Drive/PC for uninstall protection.
- `PvZ2RestoreInbox` is processed before a new reset offer, and a successful restore prevents an immediate reset offer on the restored state.
- Reset does NOT modify the original PvZ2 native purchase broker, store logic, emulator imports, saved OBB/RSB, renderer, touch, audio, or the v165 backup/restore pipeline. The historical cross-profile CLAIM bug is intentionally not claimed fixed in v166.

## Log markers / iPad acceptance

- `[V166 TEST RESET] startup result=SUCCESS protected=... error=none` (or a useful error and no reset); carried forward into the full runtime log.
- `[V163 SAVE] prelaunch skipped/failed: No existing game save to snapshot yet` is EXPECTED after successful fresh reset; a new save is generated by the game.
- `[FULLLOAD] OFFLINE STORE TEST COINS profileId=... before=... after=60000 floor=60000 markerPersisted=YES` proves the one-time grant occurred on the new profile. Observe the real visible wallet as the iPad runtime is authoritative.
- After normal gameplay, `⋯ > Sauvegarder et arrêter` must still create `[V163 SAVE] poststop SUCCESS ...`; Files/PvZ2Backups must expose a new complete snapshot of fresh A+B.
- Finally, restore the untouched external 60k reference via the already validated `PvZ2RestoreInbox`. Confirm its previous profiles/coins/purchases return. Do not uninstall at any point.
